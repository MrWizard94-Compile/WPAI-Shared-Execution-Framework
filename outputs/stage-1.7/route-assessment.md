All three routes are **NO-GO**. The [isolation matrix](isolation-matrix.json) records the exact artifact fingerprints, claim IDs, provenance, scope limits and the evidence for each decision. This analysis uses public material and the frozen repository. Installed software and local account data were outside the investigation.

## Codex CLI 0.166.0

### Authentication and account effects

**VERSION_MATCHED_SOURCE —** The pinned CLI implements four storage modes. The storage mode and the Windows keyring-backend feature are separate selections. The historic run used an existing ChatGPT subscription through a scratch profile referencing the ordinary file. That reference does not satisfy this milestone's requirement. [Pinned type definitions](https://github.com/openai/codex/blob/6ff1e1ca3b30fc8b914720681fcf5fe62e95f856/codex-rs/config/src/types.rs#L135-L173) · [Archived runner](../../work/benchmarks/stage-1.2/agent_trials.py#L148-L209).

| Mechanism | Pinned scope and limit |
|---|---|
| File | Default account backend. `auth.json` is relative to canonical `CODEX_HOME`, and the backend can truncate and save the file. Passing a different root selects a different file. Linking the ordinary file would expose it to reads and writes. [File backend](https://github.com/openai/codex/blob/6ff1e1ca3b30fc8b914720681fcf5fe62e95f856/codex-rs/login/src/auth/storage.rs#L242-L276) |
| Direct keyring | The account entry key derives from the canonical home. Windows builds include a native keyring backend. The resulting entry is namespaced in the Windows logon-token credential set. The home selector does not create an independent OS principal. This last scope comparison is `INFERENCE` from Microsoft documentation. [Direct key derivation](https://github.com/openai/codex/blob/6ff1e1ca3b30fc8b914720681fcf5fe62e95f856/codex-rs/login/src/auth/storage.rs#L285-L388) · [Windows backend](https://github.com/openai/codex/blob/6ff1e1ca3b30fc8b914720681fcf5fe62e95f856/codex-rs/keyring-store/Cargo.toml#L22-L23) · [Windows credential sets](https://learn.microsoft.com/en-us/windows/win32/api/wincred/nf-wincred-credreadw) |
| Encrypted keyring variant | Stores account data under `CODEX_HOME/secrets/codex_auth.age` with an OS-keyring-held encryption key. The `secret_auth_storage` feature defaults on in the Windows source and selects this implementation for a keyring-capable mode. The CLI storage-mode default remains file. [Path and key management](https://github.com/openai/codex/blob/6ff1e1ca3b30fc8b914720681fcf5fe62e95f856/codex-rs/secrets/src/local.rs#L171-L289) · [Windows feature](https://github.com/openai/codex/blob/6ff1e1ca3b30fc8b914720681fcf5fe62e95f856/codex-rs/features/src/lib.rs#L1140-L1145) |
| Auto | Tries the configured keyring backend before file fallback on a miss or error. Save can fall back on a keyring error. The distinct account-grant read propagates keyring errors and falls back on a miss. [Auto backend](https://github.com/openai/codex/blob/6ff1e1ca3b30fc8b914720681fcf5fe62e95f856/codex-rs/login/src/auth/storage.rs#L528-L588) |
| Ephemeral | Auth data lives in a process-memory map keyed by the resolved home. A fresh process starts without ordinary cached credentials. Explicit ephemeral mode stops before persistent fallback. This is independent of the exec flag for thread persistence. [Memory backend](https://github.com/openai/codex/blob/6ff1e1ca3b30fc8b914720681fcf5fe62e95f856/codex-rs/login/src/auth/storage.rs#L604-L644) · [Auth resolver](https://github.com/openai/codex/blob/6ff1e1ca3b30fc8b914720681fcf5fe62e95f856/codex-rs/login/src/auth/manager.rs#L1536-L1622) |

### State roots and precedence

**VERSION_MATCHED_SOURCE —** `CODEX_HOME` resolves an existing directory or defaults to `.codex` in the OS user home. The ordinary Windows preference stack builds from packaged defaults through system and cloud defaults, user config, selected profile, trusted project layers and runtime overrides. Thread-specific layers may also be inserted. Ignoring user config empties the user layer. Authentication selection, system files, effective policy and workspace discovery remain separate. The pinned Windows policy loader resolves system config from the ProgramData known folder and can select requirements via the machine `RequirementsPath` policy. Enforced requirements can pin storage mode, auth endpoint, login/workspace conditions, tool identities, web search and update behavior. [Home resolver](https://github.com/openai/codex/blob/6ff1e1ca3b30fc8b914720681fcf5fe62e95f856/codex-rs/utils/home-dir/src/lib.rs#L5-L62) · [Preference loader](https://github.com/openai/codex/blob/6ff1e1ca3b30fc8b914720681fcf5fe62e95f856/codex-rs/config/src/loader/mod.rs#L123-L535) · [Windows policy selection](https://github.com/openai/codex/blob/6ff1e1ca3b30fc8b914720681fcf5fe62e95f856/codex-rs/config/src/loader/mod.rs#L807-L838) · [Requirements fields](https://github.com/openai/codex/blob/6ff1e1ca3b30fc8b914720681fcf5fe62e95f856/codex-rs/config/src/config_requirements.rs#L164-L205).

**VERSION_MATCHED_SOURCE —** The selected home can hold logs, prompt history, sessions, archived sessions, memories, model cache and plugins. Effective SQLite config takes precedence over `CODEX_SQLITE_HOME`, which otherwise precedes the home default. The embedded exec initializes its state DB even when thread persistence is disabled. The Windows primary runtime plugin marketplace may derive from the ordinary user profile cache outside the selected home. The MCP launcher has its own inherited-environment allowlist, named inputs and overrides. The pinned TUI implements a startup update check. An exact no-update guarantee for every helper in the archived exec route is UNKNOWN. [Logs and SQLite](https://github.com/openai/codex/blob/6ff1e1ca3b30fc8b914720681fcf5fe62e95f856/codex-rs/core/src/config/mod.rs#L4314-L4344) · [State init](https://github.com/openai/codex/blob/6ff1e1ca3b30fc8b914720681fcf5fe62e95f856/codex-rs/exec/src/lib.rs#L714-L741) · [Plugin cache outside home](https://github.com/openai/codex/blob/6ff1e1ca3b30fc8b914720681fcf5fe62e95f856/codex-rs/core-plugins/src/marketplace_policy.rs#L557-L573) · [MCP environment](https://github.com/openai/codex/blob/6ff1e1ca3b30fc8b914720681fcf5fe62e95f856/codex-rs/rmcp-client/src/utils.rs#L16-L58).
